6// Subspace State-Space System Identification (N4SID / MOESP).
7//
8// Identifies a linear discrete-time state-space model from batch I/O data:
9// x[k+1] = A.x[k] + B.u[k] + w[k]
10// y[k] = C.x[k] + D.u[k] + v[k]
11//
12// Algorithm - MOESP oblique-projection variant (Verhaegen & Dewilde 1992):
13//
14// 1. Build 2i-block Hankel matrices from (Y, U):
15// Z = [U_f; W_p; Y_f] where W_p = [U_p; Y_p]
16//
17// 2. Thin LQ decomposition of Z (QR of Z') isolates the (3,2) block L32
18// which contains the oblique projection of Y_f onto W_p \perp U_f.
19//
20// 3. SVD(L32): singular values reveal system order; left singular vectors
21// form the extended observability matrix Gamma = U[:, :n].sqrt(S[:n]).
22//
23// 4. Extract C = Gamma[:p, :]
24// A = Gamma_up^T . Gamma_down (shift-invariance, least squares)
25//
26// 5. Least-squares regression for B and D from the state sequence and data.
27//
28// Data requirements:
29// - Persistent excitation: the input must excite at least n_order frequencies.
30// - N >> 2*i*(m+p): more samples -> better estimates.
31// - i >= n_order/p (i_horizon must be large enough to capture all modes).
32//
33// Output singularValues can be plotted to choose n_order: look for an elbow
34// where singular values drop sharply (signal vs. noise subspace boundary).
35//
36// Ref: Van Overschee & De Moor "Subspace Identification for Linear Systems"
37// (Kluwer 1996); Verhaegen "Identification of the Deterministic Part of
38// MIMO State Space Models" Automatica (1994).

60// n4sid: batch subspace identification.
61//
62// Y: output matrix (p * N) - rows = outputs, cols = time samples
63// U: input matrix (m * N) - rows = inputs, cols = time samples
64// n_order: desired state order n (choose by inspecting result.singularValues,
65// or use suggestOrder() below)
66// i_horizon: number of block rows in Hankel matrices (recommend i >= 2*n_order/p,
67// minimum i = n_order + 1)
68// Ts: sample time [s]
69//
70// IMPORTANT - Similarity transform:
71// The returned state-space realization (A, B, C, D) is determined only up to an
72// arbitrary similarity transform T: A_true = T*A*T^{-1}, B_true = T*B, C_true = C*T^{-1}.
73// The following quantities ARE similarity-invariant and can be trusted directly:
74// - Eigenvalues of A (system poles)
75// - I/O transfer function G(z) = C*(zI-A)^{-1}*B + D (frequency response)
76// - DC gain C*(I-A)^{-1}*B + D
77// - Stability (all |lambda(A)| < 1)
78// The following are NOT similarity-invariant and must NOT be compared to physical values:
79// - Individual entries of B, C, D
80// - State norms or covariances
81// If you need a canonical realization, apply a balancing transformation (e.g., via
82// Eigen::RealSchur) after identification. For Kalman filter use, prefer the returned
83// kalmanGain (already in the identified basis) over manual Q/R tuning.
84//
85// svd_tol: tolerance for singular value truncation (e.g. 1e-6).
86// If > 0, n_order is capped at the number of SVs > svd_tol.
87//
88// Returns a SubspaceIDResult. On failure, result.success = false and result.message
89// describes the cause.
90SubspaceIDResult n4sid(const Eigen::MatrixXd &Y,
91 const Eigen::MatrixXd &U,
92 int n_order,
93 int i_horizon,
94 double Ts,
95 double svd_tol = -1.0);

97// suggestOrder: automated system-order selection from the singular-value spectrum.
98//
99// Uses the elbow (maximum consecutive ratio) heuristic: finds the index i* at which
100// sv(i*) / sv(i*+1) is maximised (the sharpest drop in the spectrum) and returns
101// i* + 1 as the suggested order. A secondary threshold guard caps the result at
102// the first index where sv(i)/sv(0) falls below `threshold` (default 1 %).
103//
104// sv: SubspaceIDResult::singularValues from a previous n4sid call.
105// threshold: relative floor; singular values below threshold*sv(0) are treated as
106// noise. Set to 0 to disable the threshold guard.
107// maxOrder: hard cap on the returned order (-1 = no cap).
108//
109// Returns at least 1. Call after n4sid() to eliminate the manual "elbow inspection"
110// step when building adaptive loops (e.g., RLS -> n4sid -> GPC).
111int suggestOrder(const Eigen::VectorXd &sv,
112 double threshold = 0.01,
113 int maxOrder = -1);
