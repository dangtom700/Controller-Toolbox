DiscretePID lib/DiscretePID.cpp · lib/DiscretePID.h BUG — medium ▼
OKDerivative filter — backward Euler

CD(s) = Kd·N·s/(s+N). Applying backward Euler s → (z–1)/(Ts·z) and simplifying:

d[k] = α·d[k–1] + Kd·N·α·(e[k] – e[k–1])
α = 1 / (1 + N·Ts)

The code matches exactly. ✓

BUGIntegral update order — backward Euler claim violated

The header says the integral uses backward Euler, whose z-domain transfer function is I(z)/E(z) = Ki·Ts·z/(z–1). That gives the recurrence I[k] = I[k–1] + Ki·Ts·e[k], and the output should use I[k] (the updated value).

The code instead computes u_unsat with integral_ (still equal to I[k–1] at that point), then updates integral_ afterwards. The effective integral transfer function in the output path is therefore:

// Claimed (backward Euler):
I(z)/E(z) = Ki·Ts·z/(z–1)

// Actual (one-step lag):
UI(z)/E(z) = Ki·Ts / (z–1) ← forward-Euler behaviour

The two differ by a factor of z (one sample delay on the integral output). For small Ts relative to the closed-loop bandwidth the impact is small, but it is a documentation discrepancy and will produce a phase lag at higher sample rates.

Root cause in code (DiscretePID.cpp, lines 31–39):

  const double d_new   = alpha * deriv_ + p_.Kd * p_.N * alpha * (error - e_prev_);

- const double u_unsat = p_.Kp * error + integral_ + d_new;     // uses I[k-1]
  const double u_sat   = std::max(p_.uMin, std::min(p_.uMax, u_unsat));
- integral_ += p_.Ki * Ts_ * error + p_.Kb * (u_sat - u_unsat); // updated after

Fix — update integral before computing u_unsat:

+ const double ki_update = p_.Ki * Ts_ * error;                  // backward Euler increment
+ const double u_unsat   = p_.Kp * error + (integral_ + ki_update) + d_new; // uses I[k]
  const double u_sat     = std::max(p_.uMin, std::min(p_.uMax, u_unsat));
+ integral_ += ki_update + p_.Kb * (u_sat - u_unsat);            // anti-windup unchanged

Note: the anti-windup back-calculation Kb·(u_sat – u_unsat) formula is structurally correct in both versions; only the I[k] vs I[k–1] distinction changes.

DiscreteMPC lib/DiscreteMPC.cpp · lib/DiscreteMPC.h BUG — high ▼
OKPrediction matrices F and Φ

The code builds:

F(i, :) = C·A^(i+1) i = 0 … Np–1
Φ(i, j) = C·A^(i–j)·B j ≤ i, else 0

These are the standard free-response and forced-response matrices for a condensed prediction. Verified against Camacho & Bordons (2007) Eq. 4.15. ✓

OKHessian and unconstrained solve

H = Φ'·Qy·Φ + Ru is positive-definite for ρu > 0, which the code guarantees. The LDLT solve gives ΔU* = –H⁻¹·Φ'·Qy·(pred_err), and the first move is extracted and applied — all structurally correct. ✓

BUGMissing Gu·uprev term in condensed prediction

The incremental MPC formulation parametrises the input as u[k+j] = uprev + Σ Δu[l]. Expanding the output prediction from x[k] step by step:

y[k+1] = C·A·x[k] + C·B·(uprev + Δu0)
y[k+2] = C·A²·x[k] + (C·A·B + C·B)·uprev + C·A·B·Δu0 + C·B·Δu1
⋮
Y = F·x[k] + Gu·uprev + Φ·ΔU

Gu(i) = Σ_{j=0}^{i} C·A^j·B (accumulated step response)

The code's prediction error is: 

- pred_err_ = F_ * x - R_stack_;          // missing G_u * u_prev_

The gradient fed into the QP is therefore:

// Computed by code:
g = Φ'·Qy·(F·x – R)

// Correct:
g = Φ'·Qy·(F·x + Gu·uprev – R)

Whenever uprev ≠ 0, the optimiser underestimates the predicted output and computes an incorrect ΔU*. At steady state with a non-zero operating point the controller will produce a systematic offset in the incremental moves. For integrating plants the integral action in the state eventually compensates, but the transient response is degraded and the sub-optimality is present at every step.

Fix — build Gu alongside Φ in buildCondensedMatrices() and correct pred_err_:

  // In buildCondensedMatrices(), after building Phi_:
+ Gu_.resize(Np * p, m);
+ Gu_.setZero();
+ // G_u(i) = sum_{j=0}^{i} C*A^j*B  (accumulated step-response column)
+ Eigen::MatrixXd acc = plant_.C * plant_.B;   // C*A^0*B
+ for (int i = 0; i < Np; ++i) {
+     if (i > 0) acc += plant_.C * Apow[i] * plant_.B;
+     Gu_.block(i * p, 0, p, m) = acc;
+ }

  // In computeRef(), replace:
- pred_err_.noalias() = F_ * x - R_stack_;
+ pred_err_.noalias() = F_ * x + Gu_ * u_prev_ - R_stack_;

The Hessian H, LDL decomposition, and first-move extraction are unaffected by this fix.

DiscreteLeadLag lib/DiscreteLeadLag.cpp Correct ▶
OKTustin discretisation of C(s) = K·(s+zc)/(s+pc)

Applying the bilinear substitution s → 2/Ts·(z–1)/(z+1) and cross-multiplying gives the difference equation Y[k] = b₀·U[k] + b₁·U[k–1] – a₁·Y[k–1] with:

b₀ = K·(2/Ts + zc) / (2/Ts + pc)
b₁ = K·(zc – 2/Ts) / (2/Ts + pc)
a₁ = (pc – 2/Ts) / (2/Ts + pc)

All three coefficients and the sign in y = b0·u + b1·u_prev – a1·y_prev match the derivation. ✓

Phase formula: ∠C(jω) = atan2(ω, zc) – atan2(ω, pc) — verified and correct. ✓

DiscreteSMC lib/DiscreteSMC.cpp Correct ▶
OKSliding surface and boundary-layer law
s[k] = ce·e[k] + cde·(e[k] – e[k–1])
u[k] = –K·sat(s[k] / φ)

The continuous-time surface is s = ce·e + ė; the discrete approximation folds Ts into the cde parameter. This is a valid convention — the user tunes cde with units accounting for Ts. The saturation function recovers ideal sign-relay outside the boundary layer and a smooth PD law inside. ✓

DiscreteADRC lib/DiscreteADRC.cpp · lib/DiscreteADRC.h Correct ▶
OKESO bandwidth parameterisation — (s+ω₀)³ characteristic polynomial

For the 3rd-order ESO the observer error characteristic polynomial should be (s+ω₀)³ = s³ + 3ω₀s² + 3ω₀²s + ω₀³, giving observer gains:

β₁ = 3ω₀    β₂ = 3ω₀²    β₃ = ω₀³

The code sets exactly these values in updateGains(). ✓

OKForward-Euler ESO update
ε = y – z₁
z₁[k+1] = z₁[k] + Ts·(z₂[k] + β₁·ε[k])
z₂[k+1] = z₂[k] + Ts·(z₃[k] + β₂·ε[k] + b₀·u[k])
z₃[k+1] = z₃[k] + Ts·β₃·ε[k]

Code matches. The stability condition ω₀·Ts < 2 is checked at construction. ✓

OKPD control law — closed-loop poles at –ωc (double)

After disturbance cancellation the reduced plant is a double integrator ÿ ≈ u₀. Placing both poles at –ωc gives characteristic polynomial (s+ωc)² = s² + 2ωcs + ωc², so:

u₀ = ωc²·(r – z₁) – 2·ωc·z₂
u = (u₀ – z₃) / b₀

Both lines match the code exactly. ✓

KalmanFilter lib/KalmanFilter.cpp Correct ▶
OKPredict step
x̂⁻[k] = A·x̂[k–1] + B·u[k–1]
P⁻[k] = A·P[k–1]·A' + Q

Matches code. ✓

OKUpdate step — Joseph form
S = C·P⁻·C' + R
Kf = P⁻·C'·S⁻¹
ν = y – C·x̂⁻ – D·u
x̂ = x̂⁻ + Kf·ν
P = (I – KfC)·P⁻·(I – KfC)' + Kf·R·Kf'

Joseph form preserves positive-semidefiniteness numerically. All five expressions match the code. ✓

DiscreteLQR lib/DiscreteLQR.cpp Correct ▶
OKDARE value iteration
S = R + B'·P·B
Gain = S⁻¹·B'·P·A
P_new = A'·P·A – A'·P·B·Gain + Q

This is the standard Bellman backup for the infinite-horizon discrete LQR. The code implements it using A' * P as an intermediate (AtP) and avoids redundant matrix multiplications. Verified against Anderson & Moore (1990). ✓

OKOptimal gain K*
K* = (R + B'·P∞·B)⁻¹·B'·P∞·A

Extracted with the same LDLT factorisation used in the last DARE iteration — numerically clean. ✓

DiscreteLQG lib/DiscreteLQG.cpp Note ▶
OKSeparation principle ordering

The sequence predict → update → LQR is the correct causal order for output-feedback LQG. ✓

NOTEu_prev passed as u_current to KF update (D ≠ 0 only)

In step():

kf_->predict(u_prev);
kf_->update(y, u_prev);  // u_current = u_prev here

Inside KalmanFilter::update, u_current appears in the innovation as –D·u_current. The mathematically correct value at time k is u[k] (the new control, not yet computed), so u[k–1] is used instead. For plants where D = 0 — the common case — the term vanishes and there is no error. For D ≠ 0 the innovation carries a one-step lag on the feedthrough correction.

This is an inherent causality limitation of the predict-then-control structure, not a code defect, but worth documenting. Consider passing the freshly computed u[k] to a second call to update (or keeping D = 0 in the model) if the plant has significant feedthrough.

ExtremumSeeker lib/ExtremumSeeker.cpp Correct ▶
OKHPF — backward Euler first-order high-pass

Decomposing HHP(s) = 1 – ωh/(s+ωh) and applying backward Euler to the LPF pole yields the recurrence:

yh[k] = αh·(yh[k–1] + y[k] – y[k–1]) where αh = 1/(1 + ωh·Ts)

Verified analytically. The code uses hpf_state_ for yh[k–1]. ✓

OKSin×sin demodulation and gradient sign

Demodulating yh[k]·sin(ωt) with the dither sin(ωt) gives a DC component ≈ J'(θ)·a/2 after the LPF, matching the comment in the header. The gradient update:

θ[k+1] = θ[k] – sign·kint·Ts·ĝ[k]
sign = –1 for minimum, +1 for maximum

For minimum seeking: ĝ > 0 when J is increasing → θ decreases (correct gradient descent). ✓

SmithPredictor lib/SmithPredictor.cpp Note ▶
OKModified error formula
esp[k] = (r[k] – y[k]) + (ŷmodel[k] – ŷmodel[k–d])

The circular buffer (size d) correctly implements the z–d delay on the model output. Traced through for d = 2: at step k, y_buf_[buf_head_] holds ŷ_model[k–d]. ✓

OKInternal model state advance
x̂model[k+1] = A·x̂model[k] + B·u[k]

Correctly updated after computing u[k]. ✓

NOTEy_now uses D·0 instead of D·u_prev (D ≠ 0 only)
const double y_now = (model_.C * x_model_
    + model_.D * Eigen::VectorXd::Zero(model_.inputSize()))(0);

The model output should be C·x̂model + D·u[k–1] for plants with feedthrough, but the D term is forced to zero. For D = 0 (standard for physical plants) there is no effect. If the delay model is derived from a system with non-zero D, replace Zero(…) with the actual previous input.
